SESSION LESSONS
---------------
- The plan → approve → one-by-one-step cadence closed TWO phases in one
  day with clean gates; per-step "done when" rows kept every handoff
  verifiable without re-derivation.
- Live rehearsals caught what unit tests structurally could not: the
  bridge deadlock (buffer-gated recovery vs broker-side queueing) and the
  librdkafka failure-mode mismatch. Rehearse before gating.
- Goldens: inline policy keeps operator config out of behavior
  contracts; generate-then-review + a mutation test makes byte-exactness
  trustworthy. Regen-via-sed corrupts — use targeted edits or regen from
  the verified implementation.
- Kind-keyed throttle state doesn't pair escalation/de-escalation when a
  mapper overrides the kind mid-family — coalesce to a family key.
- mqtt.js v5 has no pause(); unsubscribing is lossy (broker accepts,
  nobody delivers). Persistent-session disconnect is the lossless
  backpressure; broker-side queueing is part of the design, not a detail.
- Recovery probes must not depend on the component they're recovering:
  the empty-buffer deadlock. A true round-trip probe (watermark query)
  is self-sufficient.
- EMQX + paho restart convergence takes ~40–90s (reconnect backoff +
  broker boot); soak recovery windows must absorb it. The system
  self-recovers with zero loss — measure before calling it broken.
- At-least-once duplicates are real and visible (6 in the soak around a
  broker restart); the CloudEvents id dedupe in Phase 8 is load-bearing,
  not decorative.
- Docker daemon may be down after a reboot — `open -a Docker` + poll
  before any stack-dependent work.
